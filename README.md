# Token Keeper

Локальный офлайн-менеджер API-токенов для Android (Flutter). Облака нет: всё
хранится в одном зашифрованном файле на устройстве. Сеть используется только
по явному действию: проверка токена и список моделей (кнопками или при
сохранении) и необязательная загрузка иконок (по умолчанию выключена).

## Возможности

- Локальный «аккаунт»: мастер-пароль и, по желанию, вход по биометрии.
- Карточка: название, токен, URL (необязательно), дата истечения (необязательно).
- Копирование токена в буфер с автоочисткой через 45 секунд.
- Кнопки «Копировать» у полей «Название сервиса», «Токен» и «URL» в карточке и
  у каждой модели в списке. Токен копируется с автоочисткой через 45 секунд,
  остальное — без очистки. Для пустого поля кнопка неактивна.
- Токен и URL очищаются при вставке, сохранении и проверке: удаляются пробелы,
  табы, переносы строк, неразрывные пробелы, мягкие переносы, zero-width и
  BOM. Под полем токена показывается его длина — по ней удобно сверить
  вставленный ключ с исходным. Автозамена и подсказки клавиатуры в поле
  токена выключены.
- Отправка одного токена через системное меню «Поделиться». Полный экспорт
  делается только из настроек и под отдельным паролем экспорта.
- Импорт файла экспорта с заменой данных.
- Иконка карточки: буква на цветном фоне. Загрузку иконок с сайтов можно
  включить в настройках (по умолчанию выключена, см. «Приватность»).
  Иконка ищется на корневом домене сервиса: для `https://api.deepseek.com/v1`
  это deepseek.com (регистрируемый домен по вшитому Public Suffix List),
  затем www.deepseek.com, затем сам api.deepseek.com. Поддерживаются
  `<link rel="icon">`, `shortcut icon`, `apple-touch-icon`, `/favicon.ico`,
  форматы PNG/ICO/JPEG/WebP (приводятся к PNG 128 px) и SVG (если растра нет).
- **Проверка токена** (кнопка «Проверить» и автоматически при сохранении
  новой карточки или при смене токена/URL): лёгкий запрос к API сервиса.
  Результат: действителен / недействителен или отозван (401/403, а у Gemini и
  xAI — 400 с ошибкой ключа) / нет оплаты (402) / лимит запросов (429) /
  нет сети / неизвестный сервис / ошибка сервера (5xx). Недействительный
  токен сохранению не мешает: появляется диалог «Сохранить всё равно».
- **Модели** (кнопка в карточке): список моделей с поиском, нажатие копирует
  id. Список кэшируется внутри зашифрованного хранилища вместе с датой
  обновления; при смене URL кэш сбрасывается.
- Сервис определяется по URL карточки (или по названию, если URL пуст):

  | Сервис | Запрос проверки | Авторизация |
  |---|---|---|
  | OpenAI, DeepSeek, Groq, Mistral, xAI, Together, Qwen/DashScope (CN и intl), Fireworks, Perplexity | `GET {base}/models` | `Authorization: Bearer` |
  | OpenRouter | `GET /api/v1/key` (её `/models` публичный); модели — `/api/v1/models` | `Bearer` |
  | Anthropic | `GET /v1/models` | `x-api-key` + `anthropic-version: 2023-06-01` |
  | Google Gemini | `GET /v1beta/models` | заголовок `x-goog-api-key` (не в URL) |
  | GitHub | `GET https://api.github.com/user` | `Bearer` (моделей нет) |
  | любой другой https-URL | `GET {url}/models` как OpenAI-совместимый | `Bearer` |

  Сайты вроде `platform.openai.com`, `console.anthropic.com`,
  `aistudio.google.com`, `github.com` сводятся к API-хосту сервиса.
- Просроченные карточки всегда внизу. Сортировка по дате добавления,
  названию, домену и дате истечения. Подсветка «истекает в течение 7 дней».
- Тёмная, светлая и системная тема. Автоблокировка в фоне: сразу или через
  1–10 минут. Запрет скриншотов и превью в списке задач (FLAG_SECURE).

## Криптография (формат файла v2)

- **KDF:** Argon2id v1.3, 64 МиБ, t=3, p=1 (второй рекомендованный набор
  RFC 9106), соль 16 байт. Параметры записаны в файле и при чтении
  проверяются по диапазонам. Это защищает от DoS через подделанный файл.
  Расчёт идёт в отдельном изоляте, интерфейс не зависает.
- **DEK:** случайный 256-битный ключ данных. Им зашифрованы данные
  хранилища (AES-256-GCM, свежий 96-битный nonce на каждое сохранение).
- **Обёртка DEK:** ключ из пароля шифрует DEK (AES-256-GCM). В AAD входят
  тип файла (vault/export), алгоритм, параметры KDF и соль. Подмена
  параметров в заголовке ломает проверку.
- **Смена пароля:** выпускается новый DEK и новая соль, данные
  перешифровываются, старый ключ затирается.
- **Экспорт:** отдельный файл `kind=export` со своим случайным DEK и своей
  солью. Ключ хранилища в экспорт не попадает. При импорте данные
  расшифровываются и заново шифруются локальным ключом хранилища.
- **Ошибки:** неверный пароль, повреждённый файл и файл новой версии
  различаются, и приложение показывает каждую ошибку отдельным сообщением.
  Запись атомарная: сначала временный файл, затем переименование.
- **Миграция с v1** (файлы первого MVP: PBKDF2 310k без AAD): при первом
  входе по паролю хранилище автоматически пересобирается в v2 с новым DEK,
  потому что старый DEK лежал в открытом кэше. Старый кэш
  flutter_secure_storage удаляется при каждом запуске. Экспорты v1 тоже
  можно импортировать.

## Биометрия

DEK кэшируется, только если пользователь сам включил вход по биометрии.
Тогда он шифруется ключом Android Keystore (AES-256-GCM) со следующими
свойствами:

- `setUserAuthenticationRequired(true)`: ключ работает только после
  проверки BIOMETRIC_STRONG через BiometricPrompt с CryptoObject, и так на
  каждое использование;
- `setInvalidatedByBiometricEnrollment(true)`: если добавить новый отпечаток,
  ключ становится недействительным, и приложение просит войти по паролю.

Кэш стирается при выключении биометрии, смене пароля (новый DEK), импорте,
миграции v1 и полном удалении данных. Реализация: небольшой Kotlin-канал в
`MainActivity` (`token_keeper/security`) на базе `androidx.biometric`.

## Память и блокировка

- При блокировке массив байтов DEK обнуляется, расшифрованные данные
  выбрасываются. Ключ из пароля, временные DEK и буферы открытого текста
  затираются сразу после использования.
- Автоблокировка срабатывает при уходе приложения в фон (сразу или по
  таймеру), а также при возвращении, если лимит уже истёк. На время
  системных окон (выбор файла, «Поделиться», биометрия) мгновенная
  блокировка откладывается до 1 минуты.
- **Честное ограничение:** строки Dart неизменяемы, и обнулить их нельзя.
  Токены, названия и введённые пароли живут в памяти как `String`, пока их не
  соберёт сборщик мусора. В копиях внутри полей ввода и движка Flutter
  остаётся то же самое. Расшифрованный JSON тоже проходит через строку.
  Против дампа памяти с root-доступом приложение не защищает.

## Приватность

- Загрузка иконок сайтов по умолчанию **выключена**: при ней сайты узнают,
  какими сервисами вы пользуетесь. Если загрузку выключить, кэш иконок
  удаляется. Запросы идут только по https, имена файлов кэша — SHA-256 домена.
- Проверка токена и загрузка моделей — только по нажатию или при сохранении,
  фоновых запросов нет. Токен уходит только на API-хост своего сервиса и
  только по https (http-URL не проверяются). Редиректы обрабатываются
  вручную: на тот же хост — повторяется запрос, на другой хост — запрос
  прерывается, токен туда не отправляется. Токен не пишется в логи и
  вырезается из текста ошибок сервиса.
- Блокировка хранилища отменяет активные проверки, а результат, пришедший
  после блокировки, отбрасывается (счётчик эпох сессии).
- Резервное копирование Android (`allowBackup`, перенос данных) отключено.

## Сборка

Нужны Flutter 3.50+ (Dart 3.14), Android SDK 36 и JDK 17.

```bash
flutter pub get
flutter analyze
flutter test
flutter build apk --release --target-platform android-arm64 \
  --obfuscate --split-debug-info=build/symbols
# сейчас release подписан debug-ключом; для публикации нужна своя подпись
# проверка поиска иконок по реальной сети:
TK_NETWORK_TESTS=1 flutter test test/favicon_network_test.dart
# проверка токенов по реальной сети фейковыми ключами (ожидается «недействителен»):
TK_NETWORK_TESTS=1 flutter test test/token_check_network_test.dart
# проверка настоящим ключом из файла (ключ не печатается):
TK_REAL_KEY_FILE=/path/key TK_REAL_URL=https://... flutter test test/real_key_network_test.dart
```

Минимальная версия Android — 7.0 (API 24). Разрешения: `INTERNET` (проверка
токенов, модели, иконки) и `USE_BIOMETRIC`. `MainActivity` наследует
`FlutterFragmentActivity`, этого требует BiometricPrompt.

## Структура

- `lib/crypto.dart`: KDF, AES-GCM, затирание буферов, исключения.
- `lib/container.dart`: формат файла v2/v1 и строгий разбор.
- `lib/vault_core.dart`: создание, вход, миграция, смена пароля, экспорт и импорт
  (чистый Dart, покрыт тестами).
- `lib/platform_security.dart` и `MainActivity.kt`: Keystore, биометрия, FLAG_SECURE.
- `lib/public_suffix.dart`, `lib/favicon_fetcher.dart`: eTLD+1 и поиск иконок
  (чистый Dart, `assets/public_suffix_list.dat` — копия publicsuffix.org).
- `lib/token_check.dart`: определение сервиса, проверка токена, разбор списков
  моделей, безопасные редиректы (чистый Dart, покрыт тестами с моками HTTP).
- `lib/services.dart`: сессия, настройки, автоблокировка, буфер обмена, иконки,
  `TokenService` (проверка/модели с учётом блокировки).
- `lib/screens/models_screen.dart`: экран моделей.
- `test/`: тесты криптографии, контейнера, PSL, иконок, проверки токенов,
  дымовые тесты экранов; `*_network_test.dart` — по реальной сети, по запросу.

## Ограничения

- Синхронизации между устройствами нет, и это сделано сознательно.
- Буфер обмена системный: другие приложения и клавиатуры могут его читать
  в течение 45 секунд.
- Сборка debug подписана отладочным ключом. Для публикации нужна своя подпись.
